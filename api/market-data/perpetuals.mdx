The Perpetuals endpoint gives you a real-time snapshot of key market-data fields for any perpetual futures instrument that Kairos supports. A single request returns the current mark price, index price, funding rate, next funding time, open interest, 24-hour volume, and the best bid/ask — everything you need to assess the current state of a perp market without subscribing to a full orderbook stream. No authentication is required.

---

## Get Perpetual Market Snapshot

Retrieve a live snapshot of market data for a single perpetuals instrument on the specified venue.

```
GET /v1/perpetuals/{venue}/{instrument}/snapshot
```

### Supported Venues

<Info>
  Kairos currently supports perpetuals market data from **Hyperliquid**. Additional venues will be added as integrations are completed. Use `hyperliquid` as the `venue` path parameter.
</Info>

### Parameters

<ParamField path="venue" type="string" required>
  The perpetuals venue to query. Currently supported: `hyperliquid`.
</ParamField>

<ParamField path="instrument" type="string" required>
  The instrument ticker on that venue (e.g. `BTC-PERP`, `ETH-PERP`, `SOL-PERP`). Check the [Kairos Data API perpetuals instruments endpoint](https://data.kairos.trade/perpetuals/instruments) for the full list of available tickers.
</ParamField>

### Response Fields

<ResponseField name="venue" type="string">
  The perpetuals venue this snapshot originates from (e.g. `hyperliquid`).
</ResponseField>

<ResponseField name="instrument" type="string">
  The instrument ticker as passed in the request (e.g. `BTC-PERP`).
</ResponseField>

<ResponseField name="mark_price" type="number">
  The current mark price of the perpetual, in USD. Mark price is used for unrealized PnL and liquidation calculations. It is anchored to the index price plus a funding component to prevent manipulation.
</ResponseField>

<ResponseField name="index_price" type="number">
  The current index price, in USD. This is a volume-weighted average of the spot price across reference exchanges. Mark price converges toward index price over time via the funding mechanism.
</ResponseField>

<ResponseField name="funding_rate" type="number">
  The current 8-hour funding rate as a decimal (e.g. `0.000125` = 0.0125% per 8 hours). Positive values mean longs pay shorts; negative values mean shorts pay longs.
</ResponseField>

<ResponseField name="next_funding_time" type="string">
  ISO 8601 UTC timestamp of the next funding payment settlement. Hyperliquid settles funding every 8 hours.
</ResponseField>

<ResponseField name="open_interest" type="number">
  Total notional value of all open long (or short) positions, in USD. Open interest is a measure of market participation and liquidity depth.
</ResponseField>

<ResponseField name="volume_24h" type="number">
  Total notional volume traded in the last 24 hours, in USD.
</ResponseField>

<ResponseField name="best_bid" type="number">
  Highest available bid price in the current orderbook, in USD.
</ResponseField>

<ResponseField name="best_ask" type="number">
  Lowest available ask price in the current orderbook, in USD.
</ResponseField>

<ResponseField name="snapshot_time" type="string">
  ISO 8601 UTC timestamp when this snapshot was captured by Kairos.
</ResponseField>

## Computing the Bid-Ask Spread

The `best_bid` and `best_ask` fields let you quickly compute the current spread:

```python
spread_abs = snapshot["best_ask"] - snapshot["best_bid"]
spread_bps = (spread_abs / snapshot["mark_price"]) * 10_000

print(f"Spread: ${spread_abs:.2f}  ({spread_bps:.2f} bps)")
# → Spread: $7.00  (0.65 bps)
```

## Understanding Funding Rate

The funding rate determines the periodic cash transfer between longs and shorts that keeps the perpetual price anchored to spot. Use it to estimate the carry cost of holding a position:

```python
funding_rate = snapshot["funding_rate"]         # e.g. 0.000125 per 8h
mark_price   = snapshot["mark_price"]            # e.g. 108423.50
position_size_usd = 10_000                       # your notional exposure

# Funding paid every 8 hours (3 times per day)
cost_per_8h = position_size_usd * funding_rate
cost_per_day = cost_per_8h * 3
cost_per_year = cost_per_day * 365

print(f"Funding per 8h:  ${cost_per_8h:.4f}")
print(f"Funding per day: ${cost_per_day:.4f}")
print(f"Annualized rate: {funding_rate * 3 * 365 * 100:.2f}%")
```

<Warning>
  Funding rates change every funding interval. The `funding_rate` field is a point-in-time snapshot and may differ from the rate that actually settles at `next_funding_time`. Always re-fetch the snapshot close to settlement if precision matters.
</Warning>

## Monitoring Multiple Instruments

The snapshot endpoint is per-instrument, so to monitor a portfolio of perps you need one request per instrument. Here is a simple polling pattern in Python:

```python
import requests
import time

VENUE = "hyperliquid"
INSTRUMENTS = ["BTC-PERP", "ETH-PERP", "SOL-PERP"]

def fetch_snapshots(venue, instruments):
    snapshots = {}
    for instrument in instruments:
        url = f"https://md.kairos.trade/v1/perpetuals/{venue}/{instrument}/snapshot"
        resp = requests.get(url)
        if resp.status_code == 200:
            snapshots[instrument] = resp.json()
    return snapshots

while True:
    data = fetch_snapshots(VENUE, INSTRUMENTS)
    for ticker, snap in data.items():
        print(f"{ticker:10s}  mark={snap['mark_price']:>12,.2f}  fr={snap['funding_rate']*100:.4f}%  oi=${snap['open_interest']:>15,.0f}")
    print("---")
    time.sleep(5)
```

<Tip>
  For sub-second latency on perpetuals data, use the [Market Data WebSocket](https://app.kairos.trade/docs/websocket/market-data-websocket), which streams perpetuals ticks as they occur.
</Tip>
