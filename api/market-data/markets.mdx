The Markets group of the Market Data API gives you everything you need to discover and inspect prediction markets across Polymarket, Kalshi, Predict.fun, and other supported venues. Use these endpoints to paginate the active market catalog, hydrate individual markets by ID, resolve venue-native identifiers to Kairos canonical IDs, and track a market's full resolution lifecycle — all without authentication.

---

## Markets

### List Active Markets

Paginate all currently active markets for a given provider. Results are returned in cursor-based pages so you can iterate the full catalog without missing or duplicating records.

```
GET /v1/markets
```

#### Parameters

<ParamField query="provider" type="string" required>
  The venue to query. Accepted values: `polymarket`, `kalshi`, `predictfun`.
</ParamField>

<ParamField query="limit" type="integer">
  Number of markets to return per page. Defaults to `100`. Maximum is `500`.
</ParamField>

<ParamField query="cursor" type="string">
  Opaque pagination cursor returned in the previous response. Omit on the first request.
</ParamField>

#### Example Request

```bash
curl "https://md.kairos.trade/v1/markets?provider=polymarket&limit=5"
```

#### Example Response

```json
{
  "markets": [
    {
      "market_id": "0x1234abcd...",
      "provider": "polymarket",
      "title": "Will the Fed cut rates in June 2025?",
      "category": "Economics",
      "status": "active",
      "contracts": [
        { "contract_id": "71828...", "label": "Yes" },
        { "contract_id": "31415...", "label": "No" }
      ],
      "end_date": "2025-06-30T00:00:00Z",
      "created_at": "2025-01-10T12:00:00Z"
    }
  ],
  "next_cursor": "eyJsYXN0X2lkIjoiMHgxMjM0YWJjZCJ9"
}
```

#### Response Fields

<ResponseField name="markets" type="array">
  Array of market objects for the requested page.

  <Expandable title="Market object fields">
    <ResponseField name="market_id" type="string">
      Canonical Kairos market identifier for this market.
    </ResponseField>
    <ResponseField name="provider" type="string">
      The venue this market originates from (e.g. `polymarket`).
    </ResponseField>
    <ResponseField name="title" type="string">
      Human-readable market question or title.
    </ResponseField>
    <ResponseField name="category" type="string">
      Topic category assigned by the provider (e.g. `Politics`, `Economics`, `Sports`).
    </ResponseField>
    <ResponseField name="status" type="string">
      Current market status. One of `active`, `resolved`, `suspended`.
    </ResponseField>
    <ResponseField name="contracts" type="array">
      Outcome contracts within this market. Each entry has a `contract_id` and a `label` (e.g. `Yes`, `No`).
    </ResponseField>
    <ResponseField name="end_date" type="string">
      ISO 8601 timestamp at which the market is scheduled to close/resolve.
    </ResponseField>
    <ResponseField name="created_at" type="string">
      ISO 8601 timestamp when the market was created on the provider.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="next_cursor" type="string">
  Cursor to pass as the `cursor` query parameter to retrieve the next page. `null` when you have reached the last page.
</ResponseField>

### Get One Market

Retrieve the full metadata record for a single market by its provider and market ID.

```
GET /v1/markets/{provider}/{market_id}
```

#### Parameters

<ParamField path="provider" type="string" required>
  The venue the market belongs to (e.g. `polymarket`, `kalshi`, `predictfun`).
</ParamField>

<ParamField path="market_id" type="string" required>
  The market's identifier within that provider (e.g. a Polymarket condition ID or Kalshi ticker).
</ParamField>

#### Example Request

```bash
curl "https://md.kairos.trade/v1/markets/polymarket/0x1234abcd..."
```

#### Example Response

```json
{
  "market_id": "0x1234abcd...",
  "provider": "polymarket",
  "title": "Will the Fed cut rates in June 2025?",
  "category": "Economics",
  "status": "active",
  "contracts": [
    { "contract_id": "71828...", "label": "Yes" },
    { "contract_id": "31415...", "label": "No" }
  ],
  "end_date": "2025-06-30T00:00:00Z",
  "created_at": "2025-01-10T12:00:00Z"
}
```

### Batch Fetch Markets

Fetch multiple markets by their IDs in a single request to reduce round-trips. All IDs in a single request must belong to the same provider.

```
POST /v1/markets/batch
```

#### Request Body

<ParamField body="provider" type="string" required>
  The venue all requested market IDs belong to.
</ParamField>

<ParamField body="market_ids" type="array of strings" required>
  List of market IDs to fetch. Maximum 200 per request.
</ParamField>

#### Example Request

```bash
curl -X POST "https://md.kairos.trade/v1/markets/batch" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "polymarket",
    "market_ids": ["0x1234abcd...", "0x5678efgh..."]
  }'
```

#### Example Response

```json
{
  "markets": [
    {
      "market_id": "0x1234abcd...",
      "provider": "polymarket",
      "title": "Will the Fed cut rates in June 2025?",
      "status": "active"
    },
    {
      "market_id": "0x5678efgh...",
      "provider": "polymarket",
      "title": "Will BTC exceed $120k in 2025?",
      "status": "active"
    }
  ]
}
```

### Get Tick Size

Return the price grid a venue currently enforces for one market — the same grid your limit order is validated against. Tick sizes change while a market trades (Polymarket tightens the grid near `0.04` and `0.96`), so query this before you place a limit order rather than caching a value from listing time.

```
GET /v1/markets/tick-size
```

The response describes the grid; it never snaps a price for you.

#### Parameters

<ParamField query="provider" type="string" required>
  The venue. Accepted values: `polymarket`, `kalshi`, `predictfun`.
</ParamField>

<ParamField query="contract_id" type="string" required>
  Kalshi ticker, or Polymarket condition id / market id.
</ParamField>

<ParamField query="asset_id" type="string">
  Polymarket CLOB token id. When given, the per-token grid is returned, which is where a live tick change lands first.
</ParamField>

#### Example Request

```bash
curl "https://md.kairos.trade/v1/markets/tick-size?provider=kalshi&contract_id=KXBTC15M-26JUL221600-00"
```

#### Example Response

```json
{
  "provider": "kalshi",
  "contract_id": "KXBTC15M-26JUL221600-00",
  "asset_id": null,
  "ranges": [
    { "start": "0",    "end": "0.04", "step": "0.001" },
    { "start": "0.04", "end": "0.96", "step": "0.01" },
    { "start": "0.96", "end": "1",    "step": "0.001" }
  ],
  "min_tick": "0.001",
  "source": "kalshi_price_ranges",
  "synthetic": false,
  "price_level_structure": "tapered",
  "as_of": "2026-09-18T12:00:00Z"
}
```

#### Response Fields

<ResponseField name="ranges" type="array">
  The price bands, lowest first. `step` applies to prices in `[start, end)`; the last band includes `end`.

  <Expandable title="Range object fields">
    <ResponseField name="start" type="string">Band start, decimal string.</ResponseField>
    <ResponseField name="end" type="string">Band end, decimal string.</ResponseField>
    <ResponseField name="step" type="string">Tick size within the band, decimal string.</ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="min_tick" type="string">
  The finest step anywhere on the grid, decimal string.
</ResponseField>

<ResponseField name="source" type="string">
  Where the grid came from, for example `kalshi_price_ranges` or `metadata_cache`.
</ResponseField>

<ResponseField name="synthetic" type="boolean">
  `true` when the grid was derived rather than published by the venue.
</ResponseField>

<ResponseField name="price_level_structure" type="string | null">
  `tapered` for a grid that tightens at the extremes, `null` for a flat grid.
</ResponseField>

<ResponseField name="as_of" type="string">
  When the grid was read, RFC 3339.
</ResponseField>

<Warning>
`start`, `end`, `step` and `min_tick` are decimal strings. Parse them as decimals, not floats — a float `0.001` is not exactly `0.001`, and an off-grid price is rejected by the venue.
</Warning>

Polymarket returns one flat `[0, 1]` band with `source: "metadata_cache"`. `predictfun` has no per-market tick, so it returns `{ "provider": "predictfun", "contract_id": "…", "supported": false, "reason": "…" }` rather than a fabricated grid.

#### Errors

| Status | Code | When |
|---|---|---|
| `400` | `invalid_request` | Unknown provider or empty `contract_id` |
| `404` | `not_found` | The market does not exist |
| `502` | `tick_unavailable` | The market is known but has no usable grid yet |
| `503` | `cache_cold` | Metadata is still warming; retry after `Retry-After` |

<Note>
This is the same request and response as the Data API's `GET /markets/tick-size`, with `as_of` added and no authentication required. Moving an integration over is a base-URL change.
</Note>

### Batch Tick Sizes

The same grids for up to 200 markets of **one** provider, in one round trip.

```
POST /v1/markets/tick-size/batch
```

#### Request Body

<ParamField body="provider" type="string" required>
  One provider for the whole call.
</ParamField>

<ParamField body="items" type="array" required>
  1–200 objects of `{ "contract_id": string, "asset_id"?: string }`.
</ParamField>

#### Example Request

```bash
curl -X POST "https://md.kairos.trade/v1/markets/tick-size/batch" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "polymarket", "items": [ { "contract_id": "0x…", "asset_id": "7789…" }, { "contract_id": "0x…" } ] }'
```

#### Example Response

```json
{
  "provider": "polymarket",
  "results": [
    { "provider": "polymarket", "contract_id": "0x…", "asset_id": "7789…", "ranges": [ { "start": "0", "end": "1", "step": "0.01" } ], "min_tick": "0.01", "source": "metadata_cache", "synthetic": false, "price_level_structure": null, "as_of": "2026-09-18T12:00:00Z" },
    { "contract_id": "0x…", "asset_id": null, "error": { "code": "not_found", "message": "market not found" } }
  ]
}
```

`results` is positional: `results[i]` answers `items[i]`. Each entry is a grid, the `predictfun` payload, or a per-item `error` carrying the code the single endpoint would have returned, so one bad id does not fail the batch. Responses are `Cache-Control: no-store`.

### Resolve Market Identifiers

Translate one or more venue-specific market or contract identifiers into canonical Kairos market IDs. Use this when you have raw IDs sourced from a provider's own API or UI and need to work with them in the Kairos ecosystem.

```
POST /v1/market-identifiers/resolve
```

#### Request Body

<ParamField body="identifiers" type="array of objects" required>
  List of identifier objects to resolve.

  <Expandable title="Identifier object fields">
    <ParamField body="provider" type="string" required>
      The venue the identifier originates from.
    </ParamField>
    <ParamField body="id" type="string" required>
      The raw venue-native identifier (condition ID, ticker, token ID, etc.).
    </ParamField>
  </Expandable>
</ParamField>

#### Example Request

```bash
curl -X POST "https://md.kairos.trade/v1/market-identifiers/resolve" \
  -H "Content-Type: application/json" \
  -d '{
    "identifiers": [
      { "provider": "polymarket", "id": "0x1234abcd..." },
      { "provider": "kalshi", "id": "FED-25JUN-T4.75" }
    ]
  }'
```

#### Example Response

```json
{
  "results": [
    {
      "input_id": "0x1234abcd...",
      "provider": "polymarket",
      "kairos_market_id": "km_polymarket_0x1234abcd",
      "resolved": true
    },
    {
      "input_id": "FED-25JUN-T4.75",
      "provider": "kalshi",
      "kairos_market_id": "km_kalshi_FED-25JUN-T4.75",
      "resolved": true
    }
  ]
}
```

## Resolutions

### Batch Resolution Fractions

Retrieve the current resolution fraction (i.e., the settled outcome probability or final payout) for up to 200 markets in one call. This is useful for bulk settlement checks or portfolio reconciliation.

```
GET /v1/resolutions
```

#### Parameters

<ParamField query="provider" type="string" required>
  The venue all requested market IDs belong to.
</ParamField>

<ParamField query="market_ids" type="string" required>
  Comma-separated list of market IDs to query. Maximum 200.
</ParamField>

#### Example Request

```bash
curl "https://md.kairos.trade/v1/resolutions?provider=polymarket&market_ids=0x1234abcd...,0x5678efgh..."
```

#### Example Response

```json
{
  "resolutions": [
    {
      "market_id": "0x1234abcd...",
      "provider": "polymarket",
      "resolved": true,
      "resolution_fraction": 1.0,
      "resolved_at": "2025-06-30T18:00:00Z"
    },
    {
      "market_id": "0x5678efgh...",
      "provider": "polymarket",
      "resolved": false,
      "resolution_fraction": null,
      "resolved_at": null
    }
  ]
}
```

#### Response Fields

<ResponseField name="resolutions" type="array">
  Array of resolution objects, one per queried market ID.

  <Expandable title="Resolution object fields">
    <ResponseField name="market_id" type="string">
      The market ID as passed in the request.
    </ResponseField>
    <ResponseField name="provider" type="string">
      The provider this resolution belongs to.
    </ResponseField>
    <ResponseField name="resolved" type="boolean">
      `true` if the market has reached a final resolution.
    </ResponseField>
    <ResponseField name="resolution_fraction" type="number | null">
      Final payout fraction for the winning outcome (between `0.0` and `1.0`). `null` for unresolved markets.
    </ResponseField>
    <ResponseField name="resolved_at" type="string | null">
      ISO 8601 timestamp of final resolution. `null` for unresolved markets.
    </ResponseField>
  </Expandable>
</ResponseField>

#### Parameters

<ParamField path="provider" type="string" required>

</ParamField>

<ParamField path="market_id" type="string" required>

</ParamField>

#### Example Request

```bash
curl "https://md.kairos.trade/v1/markets/polymarket/0x1234abcd.../resolution"
```

{
  "market_id": "0x1234abcd...",
  "provider": "polymarket",
  "lifecycle_state": "resolved",
  "proposed_outcome": "Yes",

## Marks

### Get Latest Marks

Fetch the most recent mark price (last trade price) for up to 200 contract/token pairs in a single request. Marks represent the last executed trade price on the contract and are a fast alternative to constructing a full orderbook mid-price.

```
GET /v1/marks
```

#### Parameters

<ParamField query="provider" type="string" required>
  The venue all contract IDs belong to.
</ParamField>

<ParamField query="contract_ids" type="string" required>
  Comma-separated list of contract (token) IDs. Maximum 200.
</ParamField>

#### Example Request

```bash
curl "https://md.kairos.trade/v1/marks?provider=polymarket&contract_ids=71828...,31415..."
```

#### Example Response

```json
{
  "marks": [
    {
      "contract_id": "71828...",
      "provider": "polymarket",
      "mark": 0.73,
      "timestamp": "2025-07-01T09:45:00Z"
    },
    {
      "contract_id": "31415...",
      "provider": "polymarket",
      "mark": 0.27,
      "timestamp": "2025-07-01T09:45:00Z"
    }
  ]
}
```

#### Response Fields

<ResponseField name="marks" type="array">
  Array of mark objects, one per queried contract ID.

  <Expandable title="Mark object fields">
    <ResponseField name="contract_id" type="string">
      The contract (token) ID as passed in the request.
    </ResponseField>
    <ResponseField name="provider" type="string">
      The venue this mark originates from.
    </ResponseField>
    <ResponseField name="mark" type="number">
      The last trade price for this contract, as a decimal between `0.0` and `1.0` (representing cents on a $1-par binary contract).
    </ResponseField>
    <ResponseField name="timestamp" type="string">
      ISO 8601 timestamp of the trade that set this mark price.
    </ResponseField>
  </Expandable>
</ResponseField>

<Tip>
  For real-time mark price updates across many contracts simultaneously, subscribe to the [Market Data WebSocket](https://app.kairos.trade/docs/websocket/market-data-websocket) instead of polling this endpoint.
</Tip>
