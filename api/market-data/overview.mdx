The Kairos Market Data API gives you read-only access to real-time and historical prediction market data — no account, no API key, and no billing setup required. Point any HTTP client at `https://md.kairos.trade` and start pulling market metadata, price candles, trade tape, resolution lifecycles, and perpetuals snapshots across every venue Kairos supports.

## Base URL

```
https://md.kairos.trade
```

All endpoints are served over HTTPS. There is no HTTP fallback.

## Authentication

No authentication is required. Every endpoint on the Market Data API is free and open. You do not need to send an `Authorization` header or register an account to call any endpoint documented here.

<Note>
  If you need order execution, PnL analytics, trader search, or advanced data features, those live on the [Execution API](https://execution.kairos.trade) and [Data API](https://data.kairos.trade), which do require an API key from [app.kairos.trade](https://app.kairos.trade).
</Note>

## Endpoint Groups

The Market Data API exposes **15 endpoints** across seven functional groups:

| Group | Endpoints | Description |
|---|---|---|
| [Markets](./markets) | 4 | Paginate active markets, fetch metadata by ID, batch-fetch, and resolve venue identifiers to canonical Kairos IDs |
| [Resolutions](./markets#resolutions) | 3 | Query resolution fractions, lifecycle snapshots, and full audit timelines for markets |
| [Marks](./markets#marks) | 1 | Fetch the latest mark (last trade price) for up to 200 contract/token pairs in one call |
| [Candles](./candles) | 2 | Retrieve single or batched OHLCV price candle series for any contract |
| [Trades](./trades) | 2 | Pull recent trade tape and aggregate volume and outcome-pressure metrics for any contract |
| [Perpetuals](./perpetuals) | 1 | Get a live market-data snapshot for any perpetuals instrument |
| Status | 2 | `GET /health` (liveness probe) and `GET /ready` (readiness probe) — return `200 OK` when the service is healthy |

## Rate Limits

The Market Data API enforces per-IP rate limits to ensure fair access. If you exceed the limit, the API returns **HTTP 429 Too Many Requests**. Handle this with exponential backoff:

```python
import time
import requests

def get_with_retry(url, max_retries=5):
    delay = 1
    for attempt in range(max_retries):
        response = requests.get(url)
        if response.status_code == 429:
            time.sleep(delay)
            delay *= 2  # exponential backoff
            continue
        response.raise_for_status()
        return response.json()
    raise RuntimeError("Rate limit exceeded after retries")
```

<Tip>
  For high-frequency data needs — orderbooks, live prices, and streaming trades — use the [Market Data WebSocket](https://app.kairos.trade/docs/websocket/market-data-websocket) instead of polling REST endpoints.
</Tip>
