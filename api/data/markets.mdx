The Data API exposes 13 market endpoints and 9 Discover endpoints that let you page through active markets, retrieve rich metadata in bulk, inspect tick grids, surface arbitrage opportunities and cross-venue clusters, and power Discover-page feeds. All endpoints require authentication unless otherwise noted.

## Authentication

```http
Authorization: Bearer <your-api-key>
```

---

## GET `/markets/active`

Enumerate active markets for a provider using a cursor-based page. Use this endpoint to walk the full market catalog for a given venue.

```bash
curl -s "https://data.kairos.trade/markets/active" \
  -H "Authorization: Bearer <your-api-key>" \
  -G \
  --data-urlencode "provider=polymarket" \
  --data-urlencode "limit=20"
```

**Parameters**

<ParamField query="provider" type="string" required>
  The venue to enumerate. One of `polymarket`, `kalshi`, or `predictfun`.
</ParamField>

<ParamField query="cursor" type="string">
  Opaque pagination cursor returned by the previous page. Omit for the first page.
</ParamField>

<ParamField query="limit" type="integer">
  Number of markets to return per page. Defaults to `100`. Maximum `500`.
</ParamField>

**Example response**

```json
{
  "markets": [
    {
      "market_id": "0xabc123",
      "provider": "polymarket",
      "title": "Will the Fed cut rates in June?",
      "status": "active",
      "category": "Economics"
    }
  ],
  "next_cursor": "eyJvZmZzZXQiOjEwMH0="
}
```

<Tip>
  Pass `next_cursor` from the response back as the `cursor` parameter on your next request to page forward through the catalog.
</Tip>

## POST `/markets/details`

Fetch name, category, status, and canonical IDs for a batch of markets identified by provider-scoped market refs. Use this when you have a list of market IDs from another source and need enriched metadata.

**Request body**

<ParamField body="markets" type="array" required>
  Array of market reference objects. Each object must include `provider` and `market_id`.
</ParamField>

```bash
curl -s -X POST "https://data.kairos.trade/markets/details" \
  -H "Authorization: Bearer <your-api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "markets": [
      {"provider": "polymarket", "market_id": "0xabc123"},
      {"provider": "kalshi", "market_id": "FED-25JUN-T5"}
    ]
  }'
```

## GET `/markets/tick-size`

Get the current valid tick grid for a market. Tick sizes change while a market trades, so query this before placing a limit order.

<Note>
The Market Data API serves the same grid at [`GET /v1/markets/tick-size`](/api/market-data/markets#get-tick-size) with no authentication and a batch variant. Prefer it for new integrations; the request parameters and response body are identical.
</Note>

**Parameters**

<ParamField query="provider" type="string" required>
  The venue (`polymarket`, `kalshi`, or `predictfun`).
</ParamField>

<ParamField query="contract_id" type="string" required>
  Kalshi ticker, or Polymarket condition id / market id.
</ParamField>

<ParamField query="asset_id" type="string">
  Polymarket CLOB token id, to read the per-token grid.
</ParamField>

```bash
curl -s "https://data.kairos.trade/markets/tick-size" \
  -H "Authorization: Bearer <your-api-key>" \
  -G \
  --data-urlencode "provider=kalshi" \
  --data-urlencode "contract_id=KXBTC15M-26JUL221600-00"
```

**Example response**

```json
{
  "provider": "kalshi",
  "contract_id": "KXBTC15M-26JUL221600-00",
  "asset_id": null,
  "ranges": [
    { "start": "0",    "end": "0.04", "step": "0.001" },
    { "start": "0.04", "end": "0.96", "step": "0.01" },
    { "start": "0.96", "end": "1",    "step": "0.001" }
  ],
  "min_tick": "0.001",
  "source": "kalshi_price_ranges",
  "synthetic": false,
  "price_level_structure": "tapered"
}
```

`start`, `end`, `step` and `min_tick` are decimal strings; `step` applies to prices in `[start, end)`. `predictfun` returns `{ "supported": false, "reason": "…" }` because the venue has no per-market tick.

  -G \

## GET `/markets/crypto/oracle-history`

</ParamField>

<ParamField query="from" type="integer">
  Start of the time range as a Unix timestamp (seconds).
</ParamField>

<ParamField query="to" type="integer">
  End of the time range as a Unix timestamp (seconds).
</ParamField>

```bash

  -H "Authorization: Bearer <your-api-key>" \
  -G \
  --data-urlencode "symbol=BTC" \
  --data-urlencode "from=1700000000" \
  --data-urlencode "to=1700086400"
```

## GET `/arb-bets/`

Get current cross-venue arbitrage opportunities from the Arb Bets feed. Each record identifies a pair of markets across venues where simultaneous YES+NO purchases yield a guaranteed profit.

**Parameters**

<ParamField query="min_profit" type="number">
  Minimum profit threshold (0–1, e.g., `0.02` for 2¢ per $1 invested).
</ParamField>

<ParamField query="limit" type="integer">
  Maximum number of opportunities to return. Defaults to `50`.
</ParamField>

```bash
curl -s "https://data.kairos.trade/arb-bets/" \
  -H "Authorization: Bearer <your-api-key>" \
  -G \
  --data-urlencode "min_profit=0.01"
```

**Example response**

```json
{
  "opportunities": [
    {
      "market_a": {"provider": "polymarket", "market_id": "0xabc123", "price": 0.47},
      "market_b": {"provider": "kalshi", "market_id": "FED-25JUN-T5", "price": 0.51},
      "implied_profit": 0.02,
      "direction": "YES_A + NO_B"
    }
  ]
}
```

<Note>
  Arbitrage windows close quickly. Always re-fetch prices immediately before executing. The Arb Bets feed reflects the last-ingested state, not a live order book.
</Note>

## GET `/market-clusters`

Get cross-venue cluster membership for a set of markets. A cluster groups markets from different venues that resolve on the same underlying event, letting you identify your cross-venue exposure.

**Parameters**

<ParamField query="market_ids" type="string" required>
  Comma-separated list of provider-scoped market IDs in the format `provider:market_id`.
</ParamField>

```bash
curl -s "https://data.kairos.trade/market-clusters" \
  -H "Authorization: Bearer <your-api-key>" \
  -G \
  --data-urlencode "market_ids=polymarket:0xabc123,kalshi:FED-25JUN-T5"
```

**Example response**

```json
{
  "clusters": [
    {
      "cluster_id": "fed-june-cut",
      "members": [
        {"provider": "polymarket", "market_id": "0xabc123"},
        {"provider": "kalshi", "market_id": "FED-25JUN-T5"}
      ]
    }
  ]
}
```

## Discover Endpoints

The Discover group provides nine endpoints that power paginated, filtered, event-grouped market feeds for the Kairos Discover page, trending tickers, breaking movers, and expiring markets. All Discover endpoints require authentication.

---

## GET `/api/markets/discover/v2`

Paginated, filtered, event-grouped market list for the Discover page. Supports filtering by category, provider, and subcategory, and returns markets grouped by their parent event.

**Parameters**

<ParamField query="provider" type="string">
  Scope to a single venue (`polymarket`, `kalshi`, `predictfun`). Omit for all venues.
</ParamField>

<ParamField query="category" type="string">
  Filter by top-level category (e.g., `politics`, `sports`, `crypto`).
</ParamField>

<ParamField query="subcategory" type="string">
  Filter by subcategory (use `/api/markets/discover/v2/subcategories` to enumerate valid values).
</ParamField>

<ParamField query="cursor" type="string">
  Opaque pagination cursor from a prior response. Omit for the first page.
</ParamField>

<ParamField query="limit" type="integer">
  Results per page. Defaults to `20`.
</ParamField>

```bash
curl -s "https://data.kairos.trade/api/markets/discover/v2" \
  -H "Authorization: Bearer <your-api-key>" \
  -G \
  --data-urlencode "category=politics" \
  --data-urlencode "limit=20"
```

## GET `/api/markets/discover/v2/search-index`

Compact, full market list optimized for client-side instant search. Returns a minimal payload — market IDs, titles, and categories — suitable for building a local search index without server round-trips on every keystroke.

```bash
curl -s "https://data.kairos.trade/api/markets/discover/v2/search-index" \
  -H "Authorization: Bearer <your-api-key>"
```

<Note>
  The search-index payload can be large. Cache it client-side and refresh on a schedule (e.g., every 5 minutes) rather than fetching on every page load.
</Note>

## GET `/api/markets/trending/ws`

Trending market IDs formatted for a live-price WebSocket subscription. Returns the current trending market ID list in a format you can pass directly to the [Kairos WebSocket stream](https://app.kairos.trade/docs/websocket/market-data-websocket) to receive real-time price updates.

```bash
curl -s "https://data.kairos.trade/api/markets/trending/ws" \
  -H "Authorization: Bearer <your-api-key>"
```

<Tip>
  Fetch `/api/markets/trending/ws` on page load to get the seed ID list, then open a WebSocket subscription for live price updates without polling.
</Tip>
