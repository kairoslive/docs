Before you can submit orders on any venue, you need to complete a one-time onboarding step for that exchange. Onboarding provisions the credentials Kairos needs to act on your behalf — or, for self-custody flows, registers your wallet with the venue's on-chain contracts. Each venue has its own requirements; this page documents every onboarding, Hyperliquid, CTF, and deposit-wallet endpoint in the Execution API.

<Note>
  Onboarding is a one-time operation per venue per wallet. Once complete, you do not need to repeat it unless you rotate credentials, import a new wallet, or explicitly invalidate your cached credentials via `POST /credentials/invalidate`.
</Note>

## Polymarket

### POST /exchanges/polymarket/enable-trading

Provision Polymarket CLOB API credentials for your connected wallet and set the on-chain ERC-20 approvals the Polymarket contracts require. This single call is all you need to go from zero to trading on Polymarket.

Under the hood it:
1. Derives a CLOB API key from your wallet signature.
2. Registers the key with Polymarket's CLOB service.
3. Calls `approve()` on USDC for the CTF Exchange and NegRisk Adapter contracts.

```bash
curl -X POST https://execution.kairos.trade/exchanges/polymarket/enable-trading \
  -H "Authorization: Bearer $KAIROS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{}'
```

```json
{
  "exchange_id": "polymarket",
  "status": "enabled",
  "clob_credentials_provisioned": true,
  "allowances_set": true,
  "wallet": "0xabc123..."
}
```

---

### POST /exchanges/polymarket/enable-imported-trading

Use this variant if you are importing an existing Polymarket wallet into Kairos — for example, a Safe or EOA that already holds pUSD or positions on Polymarket. It provisions CLOB credentials without resetting any existing wallet state.

```bash
curl -X POST https://execution.kairos.trade/exchanges/polymarket/enable-imported-trading \
  -H "Authorization: Bearer $KAIROS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "wallet_address": "0xexisting..." }'
```

## Kalshi

### POST /exchanges/kalshi/enable-trading

Connect your Kalshi account by storing its API credentials in Kairos. Unlike on-chain venues, Kalshi uses off-chain API keys that you generate in your Kalshi account settings. Kairos stores these securely and uses them to submit orders on your behalf.

<Steps>
  <Step title="Generate a Kalshi API key">
    Log in to [kalshi.com](https://kalshi.com), navigate to **Settings → API**, and create a new API key. Download the private key file.
  </Step>

  <Step title="Submit credentials to Kairos">
    POST your Kalshi API key ID and private key to the enable-trading endpoint.

    ```bash
    curl -X POST https://execution.kairos.trade/exchanges/kalshi/enable-trading \
      -H "Authorization: Bearer $KAIROS_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "api_key_id": "your-kalshi-key-id",
        "private_key": "-----BEGIN RSA PRIVATE KEY-----\n..."
      }'
    ```
  </Step>
</Steps>

```json
{
  "exchange_id": "kalshi",
  "status": "enabled",
  "credentials_stored": true
}
```

<Warning>
  Your Kalshi private key is sensitive. Transmit it only over HTTPS and consider rotating it periodically. Use `POST /credentials/invalidate` with `exchange_id: "kalshi"` to purge the stored copy from Kairos if you revoke the key at Kalshi.
</Warning>

## Hyperliquid — Two-Step Withdrawal and Transfer

Hyperliquid operations use EIP-712 signed typed data. Kairos never holds your Hyperliquid private key — you build the payload, sign it locally, and submit the signature. This ensures full self-custody for Hyperliquid fund movements.

<Steps>
  <Step title="Prepare (build unsigned typed data)">
    Call the appropriate `prepare` endpoint. Kairos returns an EIP-712 typed-data object and a short-lived `request_id`.
  </Step>
  <Step title="Sign the typed data">
    Sign the returned `typed_data` in your wallet using `eth_signTypedData_v4`.
  </Step>
  <Step title="Submit the signature">
    Call the corresponding submit endpoint with your `request_id` and `signature`.
  </Step>
</Steps>

### POST /exchanges/hyperliquid/withdraw/prepare — Prepare a Withdrawal

Build the unsigned EIP-712 payload for a Hyperliquid withdrawal request.

```bash
curl -X POST https://execution.kairos.trade/exchanges/hyperliquid/withdraw/prepare \
  -H "Authorization: Bearer $KAIROS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "amount": "100.00",
    "destination": "0xrecipient..."
  }'
```

```json
{
  "request_id": "hlw_01j9...",
  "typed_data": {
    "domain": { "name": "HyperliquidSignTransaction", "version": "1", "chainId": 42161 },
    "types": { "Withdraw": [{ "name": "amount", "type": "uint64" }, { "name": "destination", "type": "address" }] },
    "message": { "amount": 100000000, "destination": "0xrecipient..." }
  },
  "expires_at": "2025-01-15T14:35:00Z"
}
```

### POST /exchanges/hyperliquid/withdraw — Submit a Signed Withdrawal

```bash
curl -X POST https://execution.kairos.trade/exchanges/hyperliquid/withdraw \
  -H "Authorization: Bearer $KAIROS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "request_id": "hlw_01j9...",
    "signature": "0xdeadbeef..."
  }'
```

## Conditional Token Framework (CTF)

These endpoints let you interact directly with Polymarket's Gnosis Conditional Token Framework contracts — split USDC collateral into YES/NO outcome token pairs, merge them back, or redeem winning tokens after resolution.

### POST /exchanges/{exchange_id}/ctf/split — Split Collateral

Split USDC into a complete YES+NO outcome token set for a given market. For every $1.00 of USDC you split, you receive one YES token and one NO token. This is useful for market-making, hedging, or when you want to sell one side while keeping the other.

```bash
curl -X POST https://execution.kairos.trade/exchanges/polymarket/ctf/split \
  -H "Authorization: Bearer $KAIROS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "market_id": "0x1234abcd...",
    "amount_usdc": 100
  }'
```

```json
{
  "status": "confirmed",
  "market_id": "0x1234abcd...",
  "amount_split": 100,
  "yes_tokens_received": 100,
  "no_tokens_received": 100,
  "tx_hash": "0xsplittx..."
}
```

---

### POST /exchanges/{exchange_id}/ctf/merge — Merge Outcome Tokens

Merge an equal number of YES and NO tokens back into USDC. This is the reverse of split — useful when you hold both sides of a market and want to recover collateral.

```bash
curl -X POST https://execution.kairos.trade/exchanges/polymarket/ctf/merge \
  -H "Authorization: Bearer $KAIROS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "market_id": "0x1234abcd...",
    "amount": 100
  }'
```

---

### POST /exchanges/{exchange_id}/redeem — Redeem Winning Outcome Tokens

After a market resolves, redeem your winning outcome tokens for $1.00 each in USDC. Pass the `market_id` and the amount to redeem.

```bash
curl -X POST https://execution.kairos.trade/exchanges/polymarket/redeem \
  -H "Authorization: Bearer $KAIROS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "market_id": "0x1234abcd...",
    "outcome": "YES",
    "amount": 60
  }'
```

```json
{
  "status": "redeemed",
  "market_id": "0x1234abcd...",
  "outcome": "YES",
  "amount_redeemed": 60,
  "usdc_received": 60.00,
  "tx_hash": "0xredeemtx..."
}
```

## Polymarket Deposit Wallet

The deposit wallet endpoints manage a Polymarket-compatible Gnosis Safe that acts as a self-custody trading account. This is an advanced integration for users who want full on-chain custody without trusting Kairos with a private key.

| Method | Path | Description |
|---|---|---|
| `POST` | `/exchanges/polymarket/deposit-wallet/onboard` | Deploy the Safe and set trading approvals |
| `POST` | `/exchanges/polymarket/deposit-wallet/sync-balances` | Refresh Polymarket's cached balance/allowance view |
| `POST` | `/exchanges/polymarket/deposit-wallet/eoa-balances` | Read USDC and pUSD on the owner EOA |
| `POST` | `/exchanges/polymarket/deposit-wallet/safe-balances` | Read USDC, USDC.e, and pUSD on the Safe |
| `POST` | `/exchanges/polymarket/deposit-wallet/nonce` | Read the relayer nonce for the next signed batch |
| `POST` | `/exchanges/polymarket/deposit-wallet/submit-signed-batch` | Forward a client-signed batch to Polymarket's relayer |
| `POST` | `/exchanges/polymarket/deposit-wallet/signed-batch-status` | Poll the outcome of a relayed batch |
| `POST` | `/exchanges/polymarket/imported/relay-info` | Read relayer nonce and GSN relay for an imported wallet |

### POST /exchanges/polymarket/deposit-wallet/onboard

Deploy the caller's Polymarket Gnosis Safe deposit wallet and set its trading approvals in one call. Only required once per wallet.

```bash
curl -X POST https://execution.kairos.trade/exchanges/polymarket/deposit-wallet/onboard \
  -H "Authorization: Bearer $KAIROS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{}'
```

```json
{

  "allowances_set": true
}
```

### POST /exchanges/polymarket/deposit-wallet/sync-balances

### POST /exchanges/polymarket/deposit-wallet/nonce

Read the current relayer nonce for the caller's next signed batch transaction. Required when constructing a batch to submit.

```bash
curl -X POST https://execution.kairos.trade/exchanges/polymarket/deposit-wallet/nonce \
  -H "Authorization: Bearer $KAIROS_API_KEY" \

```

```json

```

### POST /exchanges/polymarket/deposit-wallet/submit-signed-batch

Forward a client-signed deposit-wallet batch to Polymarket's relayer. Build and sign the batch in your client using the nonce from the endpoint above, then submit here.

```bash

  -H "Authorization: Bearer $KAIROS_API_KEY" \
  -H "Content-Type: application/json" \

    "nonce": 7
  }'
```

```json
{
  "relay_task_id": "relay_01j9...",
  "status": "submitted"
}
```

## Resolution Check

### POST /polymarket/check-resolution

Check whether a Polymarket market has resolved and, if so, which outcome won. Use this before calling `/exchanges/polymarket/redeem` to confirm your tokens have value.

```bash
curl -X POST https://execution.kairos.trade/polymarket/check-resolution \
  -H "Authorization: Bearer $KAIROS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "market_id": "0x1234abcd..." }'
```

```json
{
  "market_id": "0x1234abcd...",
  "resolved": true,
  "winning_outcome": "YES",
  "resolved_at": "2025-01-14T20:00:00Z"
}
```

## Onboarding Checklist by Venue

<Accordion title="Polymarket">
  1. Call `POST /exchanges/polymarket/enable-trading`.
  2. Confirm `clob_credentials_provisioned: true` and `allowances_set: true` in the response.
  3. Optionally call `GET /exchanges/polymarket/allowances` to verify on-chain state.
</Accordion>

<Accordion title="Kalshi">
  1. Generate a Kalshi API key at kalshi.com.
  2. Call `POST /exchanges/kalshi/enable-trading` with your key ID and private key.
  3. Confirm `credentials_stored: true`.
</Accordion>

<Accordion title="Predict.fun">
  1. Call `POST /exchanges/predictfun/enable-trading`.
  2. Confirm `allowances_set: true`.
  3. Call `GET /exchanges/predictfun/account` to verify account status.
</Accordion>

<Accordion title="Opinion">
  1. Call `POST /exchanges/opinion/enable-trading`.
  2. Confirm `credentials_provisioned: true` and `usdt_allowance_set: true`.
</Accordion>
