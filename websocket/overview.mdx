Kairos exposes two distinct WebSocket interfaces that serve different use cases: a public market data stream for live orderbooks and price ticks, and a private Agora event stream for institutional auction participants. Both follow standard WebSocket semantics — you open a persistent TCP connection, exchange JSON (or binary) frames, and receive server-pushed messages without polling.

## Which Stream Do You Need?

Before diving into connection details, pick the right stream for your use case:

## Stream Comparison

| | Market Data WebSocket | Agora Event Stream |
|---|---|---|
| **Base URL** | `wss://md.kairos.trade` | `wss://agora.kairos.trade/v1/stream` |
| **Auth required** | No (public); optional (future private channels) | Yes — `Authorization: Bearer <key>` |
| **Message encoding** | JSON (default) or binary protobuf | JSON only |
| **Direction** | Client subscribes, server pushes | Server pushes only |
| **Purpose** | Live orderbooks, trades, price ticks | Auction lifecycle events |
| **Typical latency** | Sub-100 ms | Sub-500 ms |
| **Who uses it** | Market makers, quant traders, dashboards | Institutional block-trade participants |
| **Heartbeat** | Ping/pong frames | Keepalive events |
| **Reconnect strategy** | Exponential back-off + resubscribe | Exponential back-off + replay from cursor |

## Authentication

**Market Data WebSocket** — The stream is entirely public. You can connect and subscribe without an API key. If Kairos later introduces private channels (such as your own fills), those channels will require you to pass a bearer token during the handshake.

**Agora Event Stream** — All Agora endpoints require authentication. Pass your API key as a query parameter or in an `Authorization` header during the WebSocket upgrade:

```bash
wss://agora.kairos.trade/v1/stream?token=<your-api-key>
```

Obtain an API key at [app.kairos.trade](https://app.kairos.trade). Pass it in REST requests as:

```http
Authorization: Bearer <your-api-key>
```

<Note>
  API keys are scoped. Agora stream access requires the `agora:read` scope. Check your key's scopes in the app before connecting.
</Note>

## Message Encoding

### JSON (default)

Both streams default to JSON-encoded text frames. Every message is a UTF-8 string you parse with any standard JSON library. The market data stream uses a typed envelope:

```json
{
  "type": "orderbook_snapshot",
  "market_id": "polymarket:0xabc123",
  "sequence": 41872,
  "data": { ... }
}
```

### Binary Protobuf (market data only)

The market data WebSocket also supports a compact binary encoding using Protocol Buffers. Protobuf frames are smaller and faster to deserialize — useful at high throughput or in latency-sensitive applications. You request protobuf encoding when you subscribe. See [Protobuf Reference](/websocket/protobuf) for the complete schema and decode examples.

<Info>
  The Agora event stream does not support protobuf encoding. Agora messages are always JSON.
</Info>

## Connection Lifecycle

All Kairos WebSocket connections follow the same lifecycle:

<Steps>
  <Step title="Open the connection">
    Initiate a standard WebSocket handshake to the appropriate `wss://` URL. The server responds with `101 Switching Protocols`.
  </Step>
  <Step title="Subscribe">
    Send a JSON `subscribe` message listing the channels and market IDs you want. The server acknowledges with a `subscribed` confirmation.
  </Step>
  <Step title="Receive pushes">
    The server streams messages whenever the underlying data changes. You don't need to poll.
  </Step>
  <Step title="Handle heartbeats">
    Respond to WebSocket ping frames with pong frames. If you miss several consecutive pings, the server closes the connection.
  </Step>
  <Step title="Reconnect on disconnect">
    Network interruptions happen. Implement exponential back-off and resubscribe to all channels after reconnecting.
  </Step>
</Steps>

## Rate Limits and Back-off

Kairos applies connection-level rate limits. If you are disconnected or receive a `429` HTTP status during the upgrade handshake, wait and retry with exponential back-off:

```text
retry_delay = min(base_delay * 2^attempt + jitter, max_delay)
```

Recommended values: `base_delay = 1s`, `max_delay = 30s`, `jitter = random(0, 1s)`.

<Warning>
  Do not reconnect in a tight loop. Rapid reconnection attempts during an outage will extend your back-off window and may result in a temporary IP-level block.
</Warning>
